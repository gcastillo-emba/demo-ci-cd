# Informe de la demo — Claude Code en el POC Asuntos & Horas

Retrospectiva de F6. El POC tenía dos objetivos: (1) un sistema funcional con CI/CD, construido de punta a punta por agentes bajo MADA-MB, y (2) probar y documentar las capacidades de Claude Code que enumera el [plan maestro](plan-maestro.md) (sección "Capa Claude Code"). Este informe cubre el objetivo 2. Los números están en [métricas](metricas-demo.md), las fallas en la [bitácora](bitacora-fallas.md) (citadas como "fila N") y las mejoras a la metodología en la [propuesta de mejora](propuesta-mejora-mada.md).

## Resultado en una frase

En ≈ 9 h 30 min de reloj, con 6 decisiones humanas, se fusionaron los PRs del agente de F0 a C4 (C4 en el PR #20) y F6 cierra con este PR. Los gates mecánicos bloquearon todo lo que debían y los gates de juicio encontraron defectos que las máquinas no veían. Las fricciones vinieron sobre todo del entorno (Windows, rutas con espacios, Docker compartido) y de la política de permisos de Claude Code, no del modelo.

### Más allá de las 11: Workflows y sesiones enlazadas

- **Workflows** (`mada-capacidad`, parametrizado por `n`, `id` y `cap`): contrato, luego backend ∥ frontend en worktrees y por último la integración. Se usó en C2–C4. Funcionó como plantilla, pero el script vive en el directorio de la sesión y no en el repo. Ver la propuesta.
- **Sesiones enlazadas**: a partir de F5, cada PR independiente (runbook, fixes, migración de CodeQL, triage de Dependabot, F6) corrió en su propia sesión y worktree. El orquestador coordinó el orden de merge y los rebases `--onto`. Es la regla acordada con el usuario (propuesta, §2.1).

## Incidentes clave

### 1. Subagentes de proyecto no disponibles a mitad de sesión (fila 8)

`Agent(subagent_type: "revisor")` devolvió "not found" aunque `.claude/agents/revisor.md` existía: Claude Code registra los subagentes al iniciar la sesión. Se rodeó con un agente `general-purpose` instruido para seguir `.claude/agents/<rol>.md` al pie de la letra; las sesiones posteriores ya cargaron los roles. **Lección:** la capa `.claude/` (agentes, hooks, settings) se crea y se commitea antes de abrir la sesión orquestadora.

### 2. El clasificador del modo auto bloqueó al revisor (fila 52)

En los PRs #16 (C2) y #17, el clasificador del modo auto bloqueó `gh pr comment` y `gh pr edit` del subagente `revisor`, aunque el usuario ya lo había autorizado en el chat. El gate de juicio no pudo publicar su veredicto hasta que el usuario aprobó una regla `allow` en `.claude/settings.local.json`. C2 quedó ≈ 4 h entre abierto y fusionado, con el código listo desde las 05:43. Con la regla ya aprobada, el veredicto de C4 (PR #20) se publicó sin bloqueo. **Lección:** las reglas de permiso que necesitan los gates de juicio se provisionan en F0, versionadas y mínimas.

### 3. Colisiones de compose entre worktrees y el candado (filas 22, 25, 49)

Todos los worktrees compartían el proyecto compose `asuntos-horas`, la etiqueta de imagen `:local` y el puerto 8080. Dos E2E simultáneos se tiraban el stack: backend con código 143, API sin el código nuevo, postgres "exited (0)". La regla escrita en CLAUDE.md ("serializar") no alcanzó. El PR #13 agregó `scripts/lib/lock.mjs`, un candado entre worktrees que toman `npm run e2e` y `npm run demo:check`. CodeQL detectó que la primera versión usaba un archivo predecible en `/tmp` (fila 47), así que pasó a un directorio por usuario 0700 con retiro atómico. Desde entonces no hubo más colisiones.

### 4. Barras invertidas alteradas por heredoc/sed (fila 6, repetida)

Al escribir los hooks con heredoc desde la herramienta Bash, `\\` se colapsó a `\` y la regex de `guard-secrets` quedó inválida. Según el orquestador, el patrón se repitió en otras sesiones, y la familia incluye el CRLF introducido por escrituras con Python (fila 38). La regla "escribir código con Write/Edit, nunca heredoc" se agregó a los prompts del workflow `mada-capacidad`.

### 5. Falsos positivos y un 504 de infraestructura en CodeQL (filas 11, 19, 47, 51)

- PR #1: `js/regex-injection` en `check-ownership.mjs`, un falso positivo porque los metacaracteres se escapaban. Se reescribió el código en lugar de descartar la alerta.
- PR #5: `java/spring-disabled-csrf-protection`. CSRF no aplica a una API stateless con JWT en cabecera, pero se acotó la excepción a `/api/**`.
- PR #13: archivo temporal inseguro en el candado. Era un **positivo real**.
- PRs #19 y #20: CodeQL falló tres veces al descargar su bundle (HTTP 504 de GitHub; una en #19 y dos en #20). `seguridad` retuvo la etiqueta hasta un re-run verde: un gate no ejecutado no es un gate verde. La acción CodeQL v3 se depreca en diciembre de 2026 y su migración a v4 está en el PR #21.

### 6. PRs reemplazados tras rebase por el bloqueo de force push (fila 48)

Los PRs #11 y #12 estaban apilados sobre ramas que luego se fusionaron por squash. Rebasarlos exigía `push --force`, que `guard-git-push` bloquea a propósito. Se crearon ramas `-v2` (PRs #13 y #14) y se cerraron los originales. **Lección:** con force push prohibido, no se apilan PRs. Se ramifica desde `origin/main` y, si un PR depende de otro, el orquestador espera el merge y hace `rebase --onto` en una rama nueva.

## Lo que la fábrica de software debería adoptar

1. **MADA-MB tal como está para los gates mecánicos.** Ningún job de CI mecánico falló en un PR del agente: el gate local filtró todo antes (ver métricas).
2. **Gates de juicio con subagentes independientes**, con veredicto atado al SHA y etiquetas invalidadas en cada push (`labels-reset.yml`, `merge-si-verde.mjs`).
3. **Hooks para toda regla crítica** (secretos, push, merge, formato) y **candados para todo recurso compartido**.
4. **Una sesión por PR independiente** y subagentes o workflows solo para el paralelismo dentro de un cambio.
5. **Provisionar en F0**: subagentes, permisos de los gates de juicio, secretos o modo degradado explícito, visibilidad del repo y plan de GitHub.

## Pendientes para el humano

- **Tag `v0.1.0`**: el hook bloquea el push de tags del agente. El humano lo crea y lo empuja (`git tag -a v0.1.0 -m "v0.1.0"` y `git push origin v0.1.0`, después del merge de C4 y F6), y eso dispara `release.yml` (ver el [runbook](runbook.md), sección de release).
- PR de Dependabot #28 (dev-tooling), abierto después del triage: queda para el próximo ciclo de dependencias. Seguimientos del triage: specs con requisitos de más de 500 caracteres (para poder subir OpenSpec a ≥ 1.14.1) y ESLint 10 (requiere ADR).
- La migración de CodeQL a v4 ya está en `main` (PR #21).
